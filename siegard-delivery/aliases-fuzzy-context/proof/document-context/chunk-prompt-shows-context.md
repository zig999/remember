  why: The orchestrator's failure handling is not changed by this task and is covered by src/__tests__/unit/ingestion/extraction-orchestrator.spec.ts. No criterion here states behavior on failure. The failed preliminary reading appears only as one way a run holds no context.
- edge_case: two extractions of the same run at the same time
  why: No criterion or node of this task states concurrent behavior between runs. The only concurrency obligation, chunks of one run not overlapping, is asserted in the first and the seventh test.
- edge_case: a name or a summary that contains the closing delimiter or a newline
  why: The criteria require the context to be marked apart as data and say nothing about delimiter collisions. The JSON quoting of names is an arrangement inference of the implementation and is not pinned.
- edge_case: prompt versions after v5
  why: The registry holds v1 to v5 only, so no later version can be exercised.
